==================================================================
 COLOMBINA — RÉFÉRENCE COMPLÈTE DES CONCEPTS ET COMMANDES
 (généré le 2026-07-27, mis à jour le 2026-07-28)
==================================================================

Colombina est un bot Discord unique qui tourne sur deux serveurs :
  - 1353659915113336832 (serveur-random)  — yoru et makima y tournent aussi
  - 1297620557927284877 (serveur-lia)     — zero-two y tourne aussi

Toutes les données sont isolées par serveur (guild_id) : jouer sur un
serveur n'affecte jamais l'autre (solde, XP, gacha, tour, etc. sont
comptés séparément par guild).

------------------------------------------------------------------
 RÈGLE DE PRÉFIXE (fixe, à ne jamais casser)
------------------------------------------------------------------
  $  → économie (tout ce qui dépense/gagne des credits partagés :
       economy, market, crates, casino, crime, invest, gacha)
  .  → admin uniquement (toujours protégé par
       @commands.has_permissions(administrator=True))
  !  → tout le reste (help, profile, quest, leaderboard, tour RPG —
       la Tour dépense sa propre monnaie "Or", pas les credits
       partagés, donc elle reste en !)
  +  → consultation des logs de commandes UNIQUEMENT (une seule
       commande : `+log`, admin uniquement). Jamais utilisé pour une
       vraie action de jeu — juste pour ne jamais se confondre avec
       $/./!.

Un check global (main.py::enforce_prefix_scope) refuse silencieusement
ou avec message d'erreur toute commande utilisée avec le mauvais
préfixe. Un admin ne peut PAS utiliser une commande admin avec ! ou $.
Toute commande exécutée avec succès, sous n'importe quel préfixe, est
enregistrée dans la table `command_log` — cf. section 10.

------------------------------------------------------------------
 RESTRICTION PAR SERVEUR (duplication yoru)
------------------------------------------------------------------
Sur le serveur 1353659915113336832 (serveur-random) uniquement, les
commandes de Tour RPG, Casino et Gacha de colombina sont désactivées
(échec silencieux, aucun message) car yoru a déjà ses propres versions
de ces trois systèmes sur ce serveur (sa Tour est liée à sa ville, son
casino est plus riche, son gacha a un système d'équipement). Sur
1297620557927284877 (serveur-lia), les trois fonctionnent normalement
puisque zero-two n'a pas d'équivalent.
Économie, boutique, XP, quêtes, classement, profil restent actifs sur
les deux serveurs (pas de doublon côté yoru pour ces concepts-là).

==================================================================
 1. ÉCONOMIE — préfixe $
==================================================================

Monnaie : "credits" (table shared "economy", solde par guild+user).

  $balance
      Voir son solde de credits.

  $pay @membre <montant>
      Payer un autre membre (transfert direct, pas de taxe).

  $daily
      Récompense quotidienne : montant de base configurable via
      .config → Économie → "Montant $daily" (settings.daily_amount,
      défaut 100 credits), cooldown 24h. Série (streak) : chaque jour
      réclamé dans les 48h suivant le précédent ajoute +20 credits de
      bonus (plafonné à +500), et le streak repart à 1 si la fenêtre
      de 48h est manquée — sauf effet "streak_protection" actif (cf.
      section 3), qui préserve le streak une fois. Le nombre de jours
      consécutifs est affiché dans le message.

  $work
      Travailler pour un montant fixe configurable via .config →
      Économie → "Montant $work" (settings.work_amount, défaut 125
      credits — pas de fourchette aléatoire), cooldown 1h.

  $weekly
      2000 credits, cooldown 7 jours. Admin : `$weekly bypass` ignore
      le cooldown.

  $monthly
      8000 credits, cooldown 30 jours. Admin : `$monthly bypass` ignore
      le cooldown.

  $invest <montant>
      Investit dans "l'indice de marché" du serveur (valeur flottante
      partagée par guild, évolue à chaque investissement). Le retour
      dépend de l'indice courant + d'un tirage aléatoire ; peut être
      gagnant ou perdant. L'indice est ensuite mis à jour.

  $stocks
      Affiche l'indice de marché actuel du serveur et sa tendance
      (hausse / stable / baisse).

  $crime
      Tente un coup au hasard (pickpocket, cambriolage, arnaque...).
      60% de réussite → gagne 10-200 credits. Échec → amende de 50
      credits. Cooldown 1h (+ prison de 30 min si échec au $rob, cf.
      ci-dessous — le cooldown prison bloque aussi $crime). Admin :
      `$crime bypass` ignore cooldown/prison (le tirage réussite/échec
      reste normal).

  $rob @membre
      Tente de voler un autre joueur (doit avoir ≥100 credits).
      50% de réussite → vole 10-30% de son solde. Échec → amende de
      100 credits + 30 minutes de "prison" (bloque $crime et $rob).
      Cooldown 1h. Admin : `$rob @membre bypass` ignore cooldown/prison.

Concepts associés :
  - Cooldowns gérés en mémoire par process (CooldownManager), pas en
    base de données — redémarrer le bot réinitialise les cooldowns.
  - "bypass" : un administrateur peut ajouter le mot "bypass" en
    argument pour ignorer le coût/cooldown (utile pour les
    tests/événements). Couvre désormais $pay, $daily, $work, $weekly,
    $monthly, $buy, $key, $crime, $rob, les 8 commandes de casino
    (section 7) et $gacha pull/multi (section 8) — la sémantique est
    toujours "le coût/cooldown est ignoré, mais le résultat aléatoire
    reste tiré normalement" (jamais un gain garanti).

 2. BOUTIQUE & INVENTAIRE — préfixe $
==================================================================

  $shop
      Liste les objets en vente (nom, id, prix, description).

  $buy <id>
      Acheter un objet par son id (voir $shop). Admin : `$buy bypass <id>`
      pour obtenir l'objet sans débit.

  $sell <id>
      Revendre un objet possédé (remboursement partiel, si l'objet est
      marqué revendable).

  $inventory
      Voir son inventaire d'objets achetés + ses clés de caisses par
      rareté.

  Objets restreints à un serveur : un objet de boutique peut avoir un
  guild_id (colonne nullable sur market_items) qui le rend visible et
  achetable uniquement sur ce serveur (NULL = visible partout). Les 6
  objets "rôle" et l'objet spécial id 15 (Baddiex1) sont restreints à
  serveur-lia (1297620557927284877) et n'apparaissent pas dans le
  $shop de serveur-random.

Admin (préfixe . — sous-commandes de "market") :
  .market list
      Lister tous les objets de la boutique avec leurs ids.
  .market add <nom> <description> <prix>
      Ajouter un objet — visible uniquement sur le serveur où la
      commande est lancée (guild_id fixé automatiquement).
  .market remove <nom>
      Retirer un objet par son nom.
  .market edit <id>
      Ouvre une popup (modal Discord) pour modifier nom/prix/description.

==================================================================
 3. CAISSES / CLÉS — préfixe $
==================================================================

  $key
      Ouvre un menu à boutons (une caisse par rareté possédée : commun,
      rare, épique, légendaire, mythique, divin — 6 raretés au total,
      boutons répartis sur 3 rangées + un bouton 🎲 Aléatoire). Chaque
      ouverture consomme une clé de cette rareté et tire une
      récompense aléatoire dans la table de loot de cette rareté
      (services/crate_loot_table.py, ~32-35 entrées par palier).
      Admin : `$key bypass` pour ouvrir sans consommer de clé.

  Rareté des clés (des plus communes aux plus rares) :
      commun (60%) · rare (25%) · épique (10%) · légendaire (3.5%) ·
      mythique (1%) · divin (0.5%)  — poids utilisés pour le tirage
      quand une clé "générique" doit être attribuée (ex : drop de
      montée de niveau).

  Comment on obtient des clés :
      - En montant de niveau : chance de drop qui augmente avec le
        nombre de niveaux passés depuis le dernier drop (15% à 5
        niveaux d'écart, 25% à 10, 50% à 15, 75% à 20, 100% à 25).
      - Certaines récompenses de niveau (table "rewards") donnent
        directement une clé.
      - Certains lots de caisses donnent eux-mêmes une ou plusieurs
        clés d'une autre rareté ("Coffre commun", "Clé commune x3"...).
      - "Upgrade de clé" (voir ci-dessous) permet de faire monter une
        clé possédée d'un palier, y compris jusqu'à divin depuis
        mythique.

  Types de récompenses possibles (LootEntry.kind, services/crates.py) :
      - coins / xp : crédit direct de credits, ou XP retourné au cog
        appelant (qui l'applique via award_xp — annonces de niveau,
        rôles, etc. inclus).
      - badge / key / key_bundle : badge, une clé, ou un lot de N clés
        d'une rareté donnée.
      - cosmetic : étiquette stockée (UserCosmeticReward), affichage
        seul, aucun effet mécanique.
      - gacha_pull / gacha_pull_guaranteed / gacha_fragments /
        gacha_boost : effectue N tirages gacha gratuits immédiatement
        (personnages + historique + pity mis à jour normalement),
        force la rareté minimale d'un ou plusieurs tirages, crédite
        des fragments directement, ou pose un boost temporaire de taux
        (gacha_rate_boost, cf. section 8).
      - effect : pose un effet actif générique (services/effects.py,
        table "active_effects") — boost XP/coins temporaire, assurance
        casino, pari gratuit, double gain, boost de chance au jackpot,
        ou protection de série quotidienne (cf. sections 1, 7 et cette
        section pour le détail des types d'effets).
      - key_upgrade : consomme une clé possédée (rareté donnée ou
        choisie au hasard parmi celles possédées) et octroie une clé
        du palier supérieur.
      - bonus_open : ouvre 1 ou plusieurs caisses supplémentaires
        (même rareté ou une autre) sans consommer de clé — les
        résultats s'ajoutent à la réponse.
      - reroll : retire une deuxième fois dans la même table (en
        excluant les autres "reroll") et n'affiche que ce second tirage.
      - mystery : pioche au hasard parmi les récompenses coins/xp/key
        du même palier et résout celle-ci à la place.

  Moteur d'effets actifs (services/effects.py, table "active_effects") :
      Effets multiplicatifs (le plus fort actif est utilisé, pas
      cumulatif) : "xp_boost" (branché sur add_xp, s'applique à TOUTE
      source d'XP — chat, vocal, récompenses), "coins_boost" (branché
      sur $daily/$work/$weekly/$monthly uniquement, pas sur les gains
      de casino/gacha), "casino_jackpot_chance_boost" (multiplie
      JACKPOT_WIN_CHANCE sur $jackpot uniquement).
      Effets à usage unique/limité (consommés un par un, le plus
      ancien en premier) : "casino_insurance" (rembourse la mise en
      cas de défaite au casino), "casino_double_win" (double le gain
      net d'une victoire au casino), "casino_free_bet" (le prochain
      pari ne débite pas la mise, gain normal conservé),
      "streak_protection" (préserve le streak $daily malgré une
      fenêtre manquée).
      Effet additif : "gacha_rate_boost" (bonus de taux Mythique
      temporaire, alimente le paramètre mythique_bonus du moteur
      gacha, cf. section 8).

 4. XP / NIVEAUX / PRESTIGE — préfixe ! (sauf admin)
==================================================================

Gain d'XP :
  - Message envoyé : 5-15 XP aléatoire (anti-spam intégré, salons
    exclus possibles via .unxp).
  - Vocal : 10 XP toutes les 10 minutes passées en vocal actif (pas
    muet/sourd, au moins un autre humain présent dans le salon).
  - Réaction ajoutée à un message : +2 XP pour l'auteur du message.
  - Réaction retirée : -2 XP (jamais sous le plancher du niveau
    actuel).
  - Quête quotidienne complétée : XP + coins définis par la quête.
  - Parrainage validé : quand un filleul atteint le niveau 5, son
    parrain reçoit +200 XP et le badge "inviteur".

Garde-fou anti-alt (anti multi-compte) :
  - Un compte Discord créé il y a moins de 7 jours ne reçoit que 20%
    de l'XP gagné (minimum 1 XP), pour décourager le farming avec de
    faux comptes. Un message d'alerte est envoyé dans le salon
    configuré (`alt_account_alert_channel_id`) à l'arrivée d'un tel
    compte (cogs/anti_abuse.py).

Formule de niveau (services/leveling.py) :
  - XP requis pour atteindre le niveau N = 100 × N²
  - Niveau courant = floor(sqrt(xp / 100))
  → Progression quadratique : chaque niveau coûte plus cher que le
    précédent.

Prestige :
  - Paliers de niveau 100 / 200 / 300 / 500 → prestige 1 / 2 / 3 / 4.
  - Chaque palier de prestige multiplie TOUS les futurs gains d'XP
    (x1.1 / x1.2 / x1.3 / x1.5) et attribue un rôle Discord dédié
    (configuré via prestige_N_role_id).

Récompenses de niveau (table "rewards", exemple connu : niveau 100 →
badge "diamant") : à chaque niveau franchi, les récompenses définies
pour ce niveau sont distribuées automatiquement (badge, coins, clé de
caisse, ou rôle/titre) ET annoncées dans le salon configuré via
.config ("Annonces de niveau & récompenses", settings.level_up_channel_id).
Chaque annonce de récompense qui demande une action du joueur inclut
l'instruction pour l'utiliser (ex : une clé obtenue précise "Fais
$key pour l'ouvrir." — services/announcements.py::
format_reward_message / format_key_drop_message).

Séparément des récompenses de la table "rewards", une clé peut aussi
tomber directement à certains niveaux (5/10/15/20/25, chance
croissante — services/keys.py::KEY_DROP_CHANCES) : ce drop est
également annoncé dans le même salon, avec la même instruction
d'usage ($key).

Commandes joueur :
  !profile [@membre]
      Carte de profil (image générée) : niveau, XP, prestige, solde,
      badges — + embed : messages envoyés, temps vocal, quêtes du
      jour, clés possédées.

  !leaderboard [xp|messages|vocal]
      Classement top 10 du serveur (xp par défaut).

Admin (préfixe .) :
  .setlevel @membre <niveau>
      Force le niveau d'un membre.
  .addxp @membre <montant>
      Ajoute de l'XP (ignore le garde-fou anti-alt).
  .removexp @membre <montant>
      Retire de l'XP (jamais sous le plancher du niveau actuel).
  .givereward @membre [badge] [niveau]
      Donne un badge précis par sa clé, OU rejoue les récompenses
      d'un niveau donné (exactement un des deux arguments).
  .event-participation @membre
      Bonus ponctuel de +50 XP (ignore le garde-fou anti-alt).

  .act (cogs/reconcile.py)
      Recalcule TOUS les rôles automatiques du serveur à partir de
      l'état actuel en base, pour tout le monde d'un coup :
        - Rôles de récompense de niveau et d'accès (role_actif,
          role_bronze, role_habitue, role_argent, role_veteran,
          role_or, vip_argent, role_platine, role_diamant,
          role_mythique, role_legendaire, premium) : cumulatifs, un
          membre garde le rôle d'un palier une fois le niveau requis
          atteint (même logique que les badges). Ajoute ceux qui
          manquent, retire ceux qui ne sont plus justifiés (ex :
          après un .resetuser/.setlevel, ou un rôle donné/retiré à la
          main par erreur).
        - Rôles de prestige (Prestige I à IV) : cumulatifs de la même
          façon (prestige 2 garde le rôle prestige 1).
        - Déclenche aussi le même balayage que la tâche hebdomadaire
          de cogs/classement_roles.py (badges de classement + rôles
          exclusifs roi_du_chat/maitre_vocal/top_10), sans attendre
          les 168h.
      Ne touche jamais un rôle qui n'appartient à aucun de ces
      systèmes (ex : un rôle de couleur auto-attribué) — seuls les
      rôles gérés par ces mécaniques peuvent être retirés.

Rôles automatiques de classement (cogs/classement_roles.py) :
  - Tâche hebdomadaire (toutes les 168h) qui balaie les badges de
    classement à débloquer, puis fait tourner 3 rôles exclusifs
    ("roi_du_chat" = plus de messages, "maitre_vocal" = plus de temps
    vocal, "top_10" = plus d'XP) — un seul détenteur à la fois par
    rôle, retiré à l'ancien et donné au nouveau. Config dans
    config/leaderboard_roles.txt.

 5. QUÊTES — préfixe !
==================================================================

  !quest
      Affiche les quêtes du jour et leur progression (icône ✅/▫️,
      progression X/objectif, récompense XP+coins).

Quêtes connues (déclenchées automatiquement par l'activité, pas de

  - messages_25 : envoyer 25 messages dans la journée.
  - channels_3 : écrire dans 3 salons différents dans la journée.

récompense (XP via le même pipeline que le reste, + coins).

==================================================================
 6. INVITATIONS — automatique, pas de commande
==================================================================

Le bot suit les invitations Discord de chaque serveur (snapshot au
démarrage + sur création/usage d'invitation). Quand un nouveau membre
rejoint via une invitation, le parrain est enregistré
(invited_by_guild_id / invited_by_user_id). Le bonus de parrainage
(+200 XP + badge "inviteur") se déclenche quand le filleul atteint le
niveau 5 (cf. section XP).

 7. CASINO — préfixe $ (désactivé sur serveur-random, cf. plus haut)
==================================================================

  $coinflip <mise> [pile|face]
      Pile ou face, 50/50, gain = mise si victoire.

  $slots <mise>
      Machine à sous à 3 rouleaux (🍒🍊🍋💎7️⃣, poids 35/30/25/7/3).

  $dice <mise> <1-6>
      Devine le résultat d'un dé à 6 faces.

  $roulette <mise> <rouge|noir|vert>
      Roulette classique (0-36, vert = 0 uniquement).

  $blackjack <mise>
      Blackjack interactif contre le croupier (répondre "hit"/"stand"
      dans le chat, 30s de timeout). Croupier tire jusqu'à 17.

  $highlow <mise> <plus|moins>
      Carte de départ tirée, parie si la suivante sera plus haute ou
      plus basse.

  $poker <mise>
      Tire une main de 5 cartes, gain selon la combinaison obtenue
      (paire, brelan, full, etc.).

  $jackpot <mise>
      1% de chance de remporter toute la cagnotte progressive du
      serveur ; sinon la mise est ajoutée à la cagnotte.

  $casinostats
      Statistiques personnelles : total misé, total gagné, nombre de
      victoires, nombre de jackpots remportés (toutes les commandes
      de casino ci-dessus alimentent ces stats).

  Effets actifs (obtenus via des récompenses de caisses, cf. section 3),
  appliqués automatiquement au règlement (CasinoCog._settle) sur les 8
  commandes ci-dessus :
      - Assurance : en cas de défaite, ramène le gain à hauteur de la
        mise (remboursement, aucune perte nette).
      - Double gain : en cas de victoire, double le gain net.
      - Pari gratuit : la mise n'est jamais débitée pour ce pari (le
        gain éventuel reste crédité normalement).
      - Boost de chance au jackpot : multiplie temporairement
        JACKPOT_WIN_CHANCE (1% de base) sur $jackpot uniquement.
  Toutes les commandes acceptent aussi `bypass` en dernier argument
  pour un administrateur (mise jamais débitée, résultat tiré
  normalement — cf. section 1).

 8. GACHA — préfixe $ (désactivé sur serveur-random, cf. plus haut)
==================================================================

Système de collection de personnages (pas d'équipement/bonus de
combat — pur collectionnite). Coût fixe : 100 credits/pull, 900
credits pour un multi de 10 pulls.

  $gacha pull
      Un tirage (100 credits).
  $gacha multi
      10 tirages d'un coup (900 credits).
  $gacha rates
      Affiche les taux de chaque rareté.
  $gacha list
      Embed listant TOUS les personnages du gacha (le roster complet,
      pas seulement ceux possédés), un champ par rareté dans l'ordre
      Commun → Secret, avec le taux d'apparition en en-tête de chaque
      champ. Le palier Secret n'a aucun personnage nommé pour
      l'instant (affiche un texte l'indiquant plutôt qu'un champ vide)
      — cf. cogs/gacha.py::build_character_list_embed.
  $gacha pity
      Affiche le nombre de pulls restants avant garantie de rareté
      supérieure, + fragments possédés.
  $gacha inventory
      Liste des personnages obtenus (avec doublons comptés) +
      fragments.
  $gacha history
      Historique des derniers tirages.
  $gacha wishlist
      Affiche le personnage actuellement en wishlist.
  $gacha wishlist set <nom>
      Définit un personnage souhaité (juste indicatif/cosmétique dans
      le message de résultat, aucun effet sur les taux).
  $gacha wishlist clear
      Vide la wishlist.

Taux de rareté :
  Commun 60% · Rare 25% · Épique 10% · Légendaire 4% · Mythique 0.9%
  · Secret 0.1% (aucun personnage nommé associé au Secret — donne
  des fragments bonus).

Système de pity (garanti) :
  - Épique garanti si aucun n'est tombé depuis 10 pulls.
  - Légendaire garanti si aucun n'est tombé depuis 30 pulls.
  - Mythique garanti si aucun n'est tombé depuis 100 pulls.
  - 20% de chance d'obtenir des fragments bonus sur n'importe quel
    tirage (les tirages Secret donnent +10 fragments fixes).

$gacha pull et $gacha multi acceptent `bypass` en dernier argument pour
un administrateur (coût non débité, tirage résolu normalement).

Tirages gratuits offerts par les caisses (cf. section 3) :
  Certaines récompenses de $key effectuent directement 1 ou plusieurs
  tirages gratuits (services/gacha_actions.py::perform_pulls, la même
  fonction que $gacha pull/multi — pity, historique et fragments sont
  mis à jour normalement), forcent la rareté minimale d'un tirage
  (sans jamais rétrograder un tirage déjà meilleur), créditent des
  fragments directement, ou posent un boost temporaire de taux
  Mythique (effet actif "gacha_rate_boost", additionné au paramètre
  mythique_bonus du tirage tant qu'il est actif).

==================================================================
 9. TOUR RPG (!tour) — préfixe ! (désactivé sur serveur-random)
==================================================================

Roguelike textuel/embed en 100 étages, indépendant du reste du bot
(aucun lien avec les credits partagés — utilise sa propre monnaie
"Or"). Version simplifiée de la Tour de yoru : ici, aucun verrou de
déblocage (accessible directement, pas besoin de "posséder une
ville" puisque colombina n'a pas de système de ville).

  !tour
      Démarre une run (ou reprend celle en cours). Choix de classe au
      lancement (menu déroulant), possibilité de dépenser de l'Or
      accumulé comme or de départ. Une seule run active à la fois par
      joueur.
  !abandon
      Abandonne la run en cours ; l'or accumulé pendant la run est
      converti en Or (monnaie persistante) avant l'abandon.
  !or
      Voir son solde d'Or (monnaie propre à la Tour).
  !or convert <montant>
      Convertit de l'Or en credits partagés du serveur (1:1).
  !codex
      Voir le codex des salles/évènements uniques découverts au fil
      des runs.

Déroulé d'une run :
  - 100 étages, chacun avec des salles principales (combat, trésor,
    repos, piège, énigme, évènement) et des salles optionnelles
    (casino interne à la Tour, salle maudite).
  - Combat au tour par tour via boutons (Attaquer/Fuir), image de
    scène générée dynamiquement.
  - Boss à certains étages, boss final à l'étage 100.
  - Boutique + marché noir accessibles après chaque boss (hors final).
  - Mort = fin de run : l'or accumulé est banqué en Or persistant, un
    "death record" (étage atteint, monstres tués, or récolté) est
    enregistré, et de nouveaux achievements peuvent se débloquer.
  - Victoire à l'étage 100 : choix entre New Game+ (relance plus
    difficile, garde un bonus "legacy"), mode infini (continue au-delà
    de 100), ou arrêt.
  - Système d'achievements (services/rpg/achievements.py), de codex
    de découvertes, de traits de personnage tirés au hasard au
    lancement, et de statistiques cumulées par joueur (monstres tués,
    morts, victoires de boss sans dégât, or total gagné, étage max).

 10. ADMINISTRATION — préfixe . (has_permissions(administrator=True))
==================================================================

  .adminhelp
      Menu d'aide admin (dropdown), affiche aussi la règle de
      préfixe en pied de page.

  .config
      Affiche la configuration du bot (IDs de rôles/salons résolus
      en mentions Discord si trouvés sur le serveur, sinon signalés
      manquants) — ET permet de la modifier directement depuis Discord.
      Un bouton ✏️ Modifier ouvre un menu déroulant listant les 25
      paramètres configurables (salons dont le salon de bienvenue et
      le salon de logs admin, montants $daily/$work, rôles de
      récompense par niveau — dont le niveau 60/VIP Argent désormais
      listé entre 50 et 70 —, Premium, prestige, rôles de classement
      hebdomadaire) ; en choisir un ouvre une popup (modal). Pour les
      entrées de rôle/salon : ID Discord, mention, ou vide pour
      effacer. Pour les entrées de type "amount" ($daily/$work,
      kind="amount" dans ConfigEntry) : un nombre entier positif ou
      nul, affiché tel quel (pas de résolution de mention, jamais
      "non configuré" même à 0) — cf. services/config_editor.py::
      parse_amount_input. La modification est appliquée immédiatement
      (settings en mémoire) et persistée (.env pour les variables
      d'environnement, config/leaderboard_roles.txt pour les rôles de
      classement) pour survivre à un redémarrage. Réservé à
      l'administrateur ayant lancé la commande.

  Journalisation des commandes (cogs/admin_log.py, services/command_log.py)
      TOUTE commande exécutée avec succès, sous n'importe quel préfixe
      ($/!/./+), est enregistrée dans une table dédiée `command_log`
      (colombina-locale, sans FK vers shared.users — le log ne doit
      jamais échouer faute de ligne user existante) : guild_id,
      user_id, préfixe utilisé, nom qualifié de la commande, contenu
      exact du message tapé, horodatage. Câblé sur l'event discord.py
      `on_command_completion`, qui ne se déclenche qu'en cas de succès
      — une commande qui échoue un check (permissions, mauvais
      préfixe...) ou lève une exception n'est jamais journalisée.
      Aucune purge automatique — la table grossit indéfiniment.

      Salon de logs admin (settings.admin_log_channel_id) : configuré
      via .config → Salons → "Salon de logs admin". Une fois défini,
      en plus de l'enregistrement en base ci-dessus, chaque commande
      sous le préfixe `.` (donc chaque commande admin) déclenche EN
      PLUS un embed live dans ce salon (commande, auteur, salon
      d'origine, horodatage). Les commandes $/!/+ ne sont jamais
      postées dans ce salon (seulement enregistrées en base), pour
      éviter de le noyer sous le trafic normal des joueurs. Si aucun
      salon n'est configuré, ou si l'ID ne résout à aucun salon sur ce
      serveur, l'enregistrement en base a quand même lieu — seul
      l'embed live est sauté, silencieusement.

      +log <préfixe> <id_discord>
          Préfixe dédié `+`, réservé à cette seule commande (jamais un
          vrai préfixe de commande — cf. main.py::LOG_COMMAND_NAMES,
          même mécanisme de routage que ADMIN_COMMAND_NAMES mais
          exigeant `+` au lieu de `.`). Réservé aux administrateurs.
          Consulte `command_log` filtré par serveur + préfixe exact
          (un des `!`, `$`, `.`, `+`) + auteur, jusqu'à 20 résultats
          les plus récents. L'id peut être une mention ou un ID brut
          (parse_id_input, comme le reste de `.config`) — fonctionne
          même si le membre a quitté le serveur depuis. Les mentions
          présentes dans le contenu affiché sont désactivées
          (discord.utils.escape_mentions) pour ne pas re-notifier
          quelqu'un en réaffichant sa commande.
          Exemple : `+log ! 123456789012345678` liste les commandes à
          préfixe `!` lancées par ce membre.

  .setup welcome
      Affiche un embed d'aperçu du message de bienvenue avec un
      bouton ✏️ Modifier qui ouvre une popup (modal) à 3 champs :
      titre, texte (accepte le placeholder {membre}, remplacé par la
      mention du nouveau membre), URL d'image. Stocké dans
      config/welcome_config.json (services/welcome_config.py), pas
      dans les settings — c'est du texte libre multi-ligne, pas un ID.
      Réservé à l'administrateur ayant lancé la commande. Le salon où
      poster ce message se configure séparément via .config → Salons
      → "Salon de bienvenue" (settings.welcome_channel_id). Quand un
      salon est configuré, le bot poste automatiquement ce message
      (on_member_join, cogs/setup.py) à chaque arrivée de membre.

  .setlevel @membre <niveau>          (cf. section XP)
  .addxp / .removexp @membre <montant>   (cf. section XP)
  .addcoins @membre <montant>
      Ajoute des credits à un membre.
  .removecoins @membre <montant>
      Retire des credits (bloqué si solde insuffisant, affiche le
      solde disponible).
  .event-participation @membre        (cf. section XP)
  .givereward @membre [badge] [niveau]   (cf. section XP)
  .resetuser @membre
      Réinitialise ENTIÈREMENT un membre : XP, niveau, prestige,
      coins, badges, clés, objets, tour RPG, casino, gacha et effets
      actifs (irréversible). Équivalent à `.reset @membre all`.
  .reset @membre <monnaie|tower|casino|gacha|all>
      Il faut mentionner le membre concerné (@pseudo) — comme pour
      .money/.tower/.gacha ci-dessous, ce n'est pas un pseudo/ID en
      texte brut mais une vraie mention Discord (`membre:
      discord.Member` dans la signature de la commande).
      Réinitialise une partie ciblée de la progression d'un membre
      (irréversible, services/admin_actions.py) :
        monnaie  → solde, série quotidienne ($daily) et boost coins actif
        tower    → progression Tour RPG (étages, morts, codex,
                   succès, NG+) et solde d'Or
        casino   → stats casino et effets casino actifs (assurance,
                   pari gratuit, double gain, boost de chance)
        gacha    → pity/fragments, personnages, historique, wishlist
                   et boost de taux actif
        all      → tout ce qui précède + XP/niveau/prestige, badges,
                   clés, objets et tout effet actif restant (identique
                   à .resetuser)
      XP/niveau/badges/clés/objets ne sont réinitialisés que par la
      catégorie `all`, jamais par les catégories ciblées.
  .money add @membre <montant>
      Crédite des coins (identique à .addcoins, groupe dédié).
  .money remove @membre <montant>
      Débite des coins (identique à .removecoins ; bloqué si solde
      insuffisant).
  .money reset @membre
      Remet le solde à 0 (services/economy.py::set_balance). Ne
      touche ni la série $daily, ni les effets actifs, contrairement
      à `.reset @membre monnaie` qui est plus large.
  .tower set @membre <étage>
      Fixe l'étage max atteint (floor_reached_max) à une valeur
      exacte, y compris pour le diminuer — services/rpg_db.py::
      admin_set_floor_reached_max. Distinct de la logique de jeu
      normale (update_floor_reached_max), qui ne peut jamais faire
      redescendre l'étage max.
  .tower add / .tower remove @membre <montant>
      Ajoute/retire des étages à l'étage max atteint (jamais en
      dessous de 0) — admin_adjust_floor_reached_max.
  .tower reset @membre
      Remet l'étage max atteint à 0. Ne touche ni les morts, ni le
      codex, ni les succès, ni l'Or — contrairement à
      `.reset @membre tower` qui est plus large.
  .gacha add @membre <nom>
      Donne une copie d'un personnage précis à un membre (nom exact,
      insensible à la casse, doit exister dans
      services/gacha_logic.py::CHARACTERS_BY_RARITY — sinon rejeté,
      voir `$gacha list`). Sous-commande du groupe $gacha existant
      mais scopée préfixe `.` (cf. main.py::ADMIN_COMMAND_NAMES, qui
      route "gacha add"/"gacha remove"/"gacha reset" spécifiquement
      sur `.` sans changer le reste du groupe $gacha).
  .gacha remove @membre <nom>
      Retire une copie d'un personnage (pas de validation de nom :
      un nom introuvable/mal orthographié retourne juste "ne possède
      pas", sans planter).
  .gacha reset @membre
      Vide entièrement la collection gacha d'un membre — personnages,
      pity, fragments, historique, wishlist et boost de taux actif
      (réutilise services/admin_actions.py::reset_gacha, identique à
      `.reset @membre gacha`).
  .market add/remove/edit/list        (cf. section Boutique)
  .unxp <channel_id|list>
      Exclut un salon de l'XP vocal, ou liste les salons exclus.
  .xp <channel_id>
      Réactive l'XP vocal pour un salon précédemment exclu.

 12. GARDE-FOUS ET MÉCANISMES TRANSVERSES
==================================================================

  - Anti-spam messages : si un joueur envoie plus de 10 messages en
    moins de 2 secondes (rafale), son gain d'XP par message est coupé
    pendant 10 minutes (pas juste le message en rafale — toute la
    fenêtre de mute, même si le rythme ralentit ensuite). Les stats
    de messages/quêtes continuent d'être comptées normalement, seul
    l'XP est coupé. Le déclenchement de la coupure est annoncé une
    seule fois (pas à chaque message supprimé) dans le salon configuré
    via `admin_log_channel_id` (.config), avec un embed indiquant
    l'utilisateur, le salon et la durée de la sanction
    (services/spam_guard.py, cogs/leveling.py::on_message).
  - Anti-alt : cf. section XP (comptes < 7 jours pénalisés à 20% d'XP).
  - Isolation stricte par serveur (guild_id) sur absolument toutes
    les données : solde, XP, niveau, prestige, badges, clés,
    inventaire, casino, gacha, Or/Tour RPG, quêtes, classement.
  - "bypass" admin : mot-clé accepté en argument sur toutes les
    commandes qui dépensent une ressource ($pay, $daily, $work,
    $weekly, $monthly, $buy, $key, $crime, $rob, les 8 commandes de
    casino, $gacha pull/multi) pour que les administrateurs puissent
    ignorer coût/cooldown à des fins de test ou d'événement — le
    résultat aléatoire de la commande reste toujours tiré normalement,
    jamais un gain garanti. Nécessite is_admin(ctx.author).
  - Moteur d'effets actifs (services/effects.py, table
    "active_effects") : effets temporaires/à usages limités posés par
    certaines récompenses de caisses ($key, cf. section 3) et
    consommés par les systèmes économie/casino/gacha au moment
    pertinent (boosts XP/coins, assurance/pari gratuit/double gain au
    casino, boost de chance au jackpot, protection de série
    quotidienne, boost de taux gacha).
  - Salons sans XP : un salon peut être exclu de l'XP (texte ET/OU
    vocal selon la commande utilisée) via .unxp.

 13. SUGGESTIONS DE FONCTIONNALITÉS -> IMPLÉMENTATION AUTOMATIQUE
==================================================================

  Pipeline de bout en bout permettant à un membre de proposer une
  fonctionnalité qui, une fois validée par deux administrateurs
  précis, est implémentée et déployée automatiquement sans
  intervention manuelle (cogs/suggestions.py).

  1. !suggest <idée> — utilisable uniquement dans le salon configuré
     via `suggestion_channel_id` (.config). Publie un embed dans le
     salon `suggestion_validation_channel_id` (.config) avec deux
     boutons Accepter/Refuser.
  2. Seuls deux comptes Discord précis (IDs codés en dur dans
     cogs/suggestions.py::SUGGESTION_APPROVER_IDS, non éditables via
     .config — garde-fou volontairement hors de portée d'un admin qui
     compromettrait la config) peuvent cliquer ces boutons. Toute
     autre personne reçoit un refus ephemeral.
  3. Refus : le message est mentionné comme refusé par l'approbateur
     dans le salon de suggestions, et loggé dans
     `admin_log_channel_id`.
  4. Acceptation : un entretien de clarification démarre avec
     DeepSeek (services/deepseek_client.py, clé `deepseek_api_key`)
     dans le salon de suggestions — jusqu'à 5 questions
     (MAX_CLARIFICATION_QUESTIONS), une par message, jusqu'à ce que
     l'IA juge avoir assez d'informations (ou que la limite soit
     atteinte) et rédige un prompt final complet pour Claude Code.
  5. Le prompt final est écrit dans un fichier de tâche
     (automation_queue/pending/<id>.json,
     services/suggestion_queue.py) — c'est le pont entre Discord et
     Claude Code.
  6. Un processus séparé sur l'hôte (scripts/run_pending_suggestions.py,
     lancé en continu via le service systemd utilisateur
     colombina-suggestion-runner.service) surveille ce dossier et,
     pour chaque tâche : invoque `claude -p` en mode headless
     (--dangerously-skip-permissions) avec un prompt encadré qui
     restreint les modifications à colombina/ et shared/, puis lance
     la suite de tests complète (même pattern docker que le
     développement), et seulement si les tests passent, rebuild +
     redeploy automatiquement le container (docker compose build/up).
     Si Claude Code échoue ou si les tests échouent, le déploiement
     est annulé (jamais de code cassé poussé en prod), et le résultat
     est écrit dans automation_queue/failed/ au lieu de
     automation_queue/done/.
  7. Le cog surveille automation_queue/done/ et failed/ (boucle de
     fond, 15s) et poste le résultat (succès + déployé, ou échec avec
     l'étape et la fin du log) dans le salon d'origine en mentionnant
     le demandeur, avec une copie dans `admin_log_channel_id`.

  Le seul garde-fou humain de tout le pipeline est la validation à
  deux sur Discord (étape 2) — tout le reste, y compris l'écriture de
  code et le déploiement en production, est automatique.
